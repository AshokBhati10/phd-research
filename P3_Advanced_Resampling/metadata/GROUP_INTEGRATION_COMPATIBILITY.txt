#### Known Differences

1. **SMOTE-ENN Implementation (Staged Pipeline)**

   - **Person 1**: SMOTE-ENN was implemented with imbalanced-learn's default pipeline; exact runtime details
     not disclosed in the public protocol.

   - **Person 3**: SMOTE-ENN was implemented as an explicit two-stage staged pipeline with checkpointing
     for robustness. This is an **engineering implementation detail only**; the scientific operation is identical:
     SMOTE is applied first, then ENN is applied second, with `random_state=42` throughout.

   - **Effect on Results**: NONE. The staged implementation preserves determinism (`random_state=42` at each
     stage) and produces bit-identical output to a non-staged sequential application (verified during pilot
     validation). The checkpointing mechanism is a fallback for runtime reliability and does not alter
     methodology or numerical results.

   - **Why Staged**: During pilot experimentation, iterative ENN convergence on 3M balanced samples
     (post-SMOTE) exhibited unpredictable timeout behavior. The staged pipeline with checkpointing was
     introduced to allow safe resumption if convergence stalled, without requiring code modifications
     to the core algorithm parameters. No algorithm parameters were changed.

2. **Checkpoint/Resume Mechanism**

   - Person 3 uses explicit checkpoint tracking (`checkpoint.json`) to avoid re-running completed experiments.
     This is a standard best practice and does not affect scientific results—each (technique, model)
     pair is independent and fully deterministic given `random_state=42`.

3. **Test Set Fingerprinting**

   - Both Person 1 and Person 3 verify the test set fingerprint before and after experiments.
     Person 3 adds explicit abort-on-mismatch logic to prevent accidental leakage.

#### Direct Mergeability

- All 12 Person 3 results can be directly compared with Person 1's results using the same
  (technique, model) index.
- **Caveat 1**: Person 1 may have used a different (or no) random seed for the train/test split;
  the exact split algorithm and seed should be verified before claiming that "Person 1 ≠ Person 3"
  differences are due to resampling methodology rather than data split variance. **Recommended**:
  confirm that Person 1 used `random_state=42` for the split.
- **Caveat 2**: SMOTE-ENN's staged implementation is equivalent to sequential application but
  may exhibit microscopically different floating-point rounding during the interpolation phase
  if Person 1 used a different order-of-operations. **Recommended**: if bit-identical SMOTE-ENN
  results are critical, re-run both implementations on a shared test dataset (e.g., pilot data)
  to confirm equivalence.
- **Caveat 3**: The test set is documented as "frozen"; the specific rows and their order matter
  for reproducibility. **Recommended**: exchange test-set fingerprints with Person 1 to confirm
  that the datasets are identical.
